# 跨维度一致性检查 Rubric (XC-1–XC-8)

XC 跨维度一致性检查项。基于 ITERATION-DOCUMENT-CHECKLIST v2.1 §4.1。

XC 检查项缺少任一相关域产物时标记 `SKIPPED`（原因：`missing_domain:{domain_id}`），不计入 BLOCK/WARN。

---

## XC-1 — 指标 ↔ AC 对齐

**引用域**：D1 + D2

| PASS | FAIL |
|------|------|
| 每个成功指标至少有 1 条对应 AC | 有指标无对应 AC |

**检查方法**：从 D1 提取成功指标列表，从 D2 提取 AC 列表，逐项匹配。

## XC-7 — UX 交互 ↔ 产品用户旅程对齐

**引用域**：D2 + D3

| PASS | FAIL |
|------|------|
| 产品用户旅程的每步有对应 UX 交互 | 产品旅程步骤无对应 UX 交互 |
| UX 交互流程与产品主路径、分支路径、异常路径一致 | UX 交互与产品旅程矛盾或遗漏异常恢复 |
| UX 错误状态覆盖产品异常路径 | 产品异常路径无对应错误状态 UX |

**检查方法**：从 D2 提取用户旅程（主路径、分支路径、异常路径），从 D3 提取 UX 交互流程和错误状态，逐项匹配。

**SKIP / N/A 规则**：若 D2 PRD 明确声明纯后端/无人工交互，或“用户旅程不适用”并给出原因，则 XC-7 标记 `SKIPPED`（原因：`not_applicable:no_user_interaction`）。若 D2 有用户旅程但缺少 D3 UX 文档，按 `missing_domain:D3` 标记 `SKIPPED`；若 D3 存在但未覆盖 D2 用户旅程，则按上表判 FAIL。

---

## XC-8 — 实施范围 ↔ 架构分层对齐

**引用域**：D4 + D6

| PASS | FAIL |
|------|------|
| 实施范围与架构分层一致 | 实施范围与架构分层矛盾 |
| 修改的模块在架构图中有对应位置 | 修改的模块在架构图中无位置 |

**检查方法**：从 D4 提取架构分层，从 D6 提取实施范围，检查一致性。
