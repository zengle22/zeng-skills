# 工程实施检查 Rubric (EI-1–EI-5)

D6 工程实施域检查项。基于 ITERATION-DOCUMENT-CHECKLIST v2.1 §2.6。

---

## EI-1 — 实施范围边界

**MAC**：精确到目录级 + >= 3 个修改文件类型

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 实施范围精确到目录级 | 范围过于笼统（如"后端模块"） |
| 至少列出 3 种修改文件类型（如 .ts、.py、.sql） | 文件类型少于 3 种 |
| 明确标注不修改的区域 | 无排除说明 |
| 涉及数据库的有迁移文件说明 | 有数据库变更但无迁移说明 |

**Prompt 约束**：请逐项列出修改的目录和文件类型。输出目录总数和文件类型总数。

---

## EI-2 — 关键实现决策

**MAC**：同步/异步、锁策略、缓存等已拍板

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 同步/异步决策已拍板 | 未决策 |
| 锁策略已拍板（如有并发） | 有并发但未决策 |
| 缓存策略已拍板（如有缓存） | 有缓存但未决策 |
| 关键决策有理由说明 | 决策无理由 |

---

## EI-3 — 依赖关系

**MAC**：前置 Phase/Feature/PR 已明确

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有前置依赖清单 | 无依赖清单 |
| 每个依赖有状态说明（已完成/进行中/未开始） | 依赖无状态说明 |
| 依赖阻塞关系明确 | 阻塞关系不明确 |
| 有依赖变更的应对方案 | 无应对方案 |

---

## EI-4 — 回滚与降级策略

**MAC**：回滚步骤 + 降级方案明确

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有回滚步骤说明 | 无回滚步骤 |
| 回滚步骤可执行（有具体命令/操作） | 回滚步骤不可执行 |
| 有降级方案说明 | 无降级方案 |
| 降级方案有触发条件 | 降级方案无触发条件 |
| 涉及数据库的有数据回滚方案 | 有数据库变更但无数据回滚 |

---

## EI-5 — 性能与容量预估

**MAC**：数据量/QPS/Token 消耗/存储增长

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有数据量预估（初始/增长） | 无数据量预估 |
| 有 QPS 预估（峰值/均值） | 无 QPS 预估 |
| 涉及 AI 的有 Token 消耗预估 | 涉及 AI 但无 Token 预估 |
| 有存储增长预估 | 无存储增长预估 |
| 预估数据有来源说明 | 预估无来源说明 |
