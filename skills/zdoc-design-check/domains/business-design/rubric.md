# 商业设计检查 Rubric (BD-1–BD-6)

D1 商业设计域检查项。基于 ITERATION-DOCUMENT-CHECKLIST v2.1 §2.1。

---

## BD-1 — 迭代类型确认

**MAC**：二选一明确标注

| PASS | FAIL |
|------|------|
| 明确标注"功能迭代"或"商业迭代" | 未标注 |

---

## BD-2 — 用户画像

**MAC**：商业迭代必填；功能迭代标注复用

| 迭代类型 | PASS 条件 | FAIL 条件 |
|---------|----------|----------|
| 商业迭代 | 有用户特征 + 使用场景 + 使用频率 | 任一缺失 |
| 功能迭代 | 标注"复用现有用户画像"并引用来源 | 未标注 |

---

## BD-3 — 业务价值

**MAC**：至少 1 个痛点 + 1 个不做代价

| 迭代类型 | PASS 条件 | FAIL 条件 |
|---------|----------|----------|
| 商业迭代 | 有具体痛点描述 + 不做的代价 | 任一缺失 |
| 功能迭代 | 可简化为一句话价值陈述 | 完全缺失 |

---

## BD-4 — 范围边界

**MAC**：Out of Scope >= 3 项，每项可独立判断

| PASS 条件 | FAIL 条件 |
|----------|----------|
| Out of Scope >= 3 项 | Out of Scope < 3 项 |
| 每项具体到可独立判断 | 含笼统描述（"其他XX"、"类似功能"）|
| 不含模糊限定词 | 含"等"、"等等"、"其他"等模糊词 |

**具体性判定规则**：
- "本期不做微信支付" -> 可独立判断 -> PASS
- "本期不支持离线模式" -> 可独立判断 -> PASS
- "本期不做 iOS 端" -> 可独立判断 -> PASS
- "本期不做其他支付方式" -> 无法判断"其他"包含什么 -> FAIL
- "本期不做类似功能" -> 无法判断"类似"的边界 -> FAIL

**Prompt 约束**：请逐项列出 Out of Scope 内容，判断每项是否可独立判断。输出 Out of Scope 总数和不可独立判断项数。

---

## BD-5 — 成功指标

**MAC**：可量化 + 目标值 + 测量方式 + 基准

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 至少 1 个可量化指标 | 无指标或指标不可量化 |
| 有目标值 | 无目标值 |
| 有测量方式 | 无测量方式 |
| 有基准数据或假设来源 | 无基准也未标注假设 |

**可量化性判定规则**：
- "DAU 提升 20%" -> 可量化 -> PASS
- "用户满意度 NPS >= 40" -> 可量化 -> PASS
- "提升用户体验" -> 不可量化 -> FAIL
- "提高用户活跃度" -> 不可量化（无具体指标） -> FAIL

---

## BD-6 — 优先级

**MAC**：P0 <= 3，每个有"不做就失败"理由

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有 P0/P1/P2 划分 | 无优先级划分 |
| P0 不超过 3 个 | P0 > 3 个 |
| 每个 P0 有"不做就失败"理由 | P0 无理由 |

**Prompt 约束**：请逐项列出 P0 功能，计数 P0 总数。输出 P0 总数和每个 P0 的理由。
