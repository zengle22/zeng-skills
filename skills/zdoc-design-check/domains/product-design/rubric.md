# 产品设计检查 Rubric (PD-1–PD-7)

D2 产品设计域检查项。基于 ITERATION-DOCUMENT-CHECKLIST v2.1 §2.2。

---

## PD-1 — 问题陈述

**MAC**：有背景 + 痛点 + 根本原因

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有背景描述（当前状态/现状） | 无背景描述 |
| 有痛点描述（用户/业务遇到的问题） | 无痛点描述 |
| 有根本原因分析（为什么会出现这个问题） | 仅描述现象，无原因分析 |

---

## PD-2 — 用户故事完整性

**MAC**：US-XXX 编号 + AS A/I WANT/SO THAT 格式

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 每条用户故事有 US-XXX 编号 | 无编号 |
| 包含 AS A（角色）+ I WANT（功能）+ SO THAT（价值）格式 | 格式不完整 |
| 用户故事数量 >= 1 | 无用户故事 |

**Prompt 约束**：请逐条列出用户故事，检查编号格式和 AS A/I WANT/SO THAT 结构。输出用户故事总数和格式不完整数。

---

## PD-3 — AC 可测性

**MAC**：每条 AC 通过可测三问

每条 AC 必须回答三个问题：
1. **怎么触发**（Given / 前置条件）
2. **怎么做**（When / 操作步骤）
3. **怎么判定通过**（Then / 预期结果）

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 每条 AC 可回答"怎么触发" | AC 缺少触发条件 |
| 每条 AC 可回答"怎么判定通过" | AC 缺少判定标准 |
| 预期结果具体可验证 | 预期结果模糊（如"正常工作"） |

---

## PD-4 — 业务规则完整性

**MAC**：公式/阈值/频率/Guardrail 均有定义

| 检查项 | PASS 条件 | FAIL 条件 |
|--------|----------|----------|
| 计算公式 | 涉及计算的规则有明确公式 | 有计算但无公式 |
| 阈值定义 | 涉及阈值的规则有具体数值 | 有阈值但无数值 |
| 执行频率 | 涉及定时的规则有频率说明 | 有定时但无频率 |
| Guardrail | 涉及限制的规则有上下界 | 有限制但无边界 |

---

## PD-5 — 异常流程覆盖

**MAC**：业务异常 + 系统异常两层均有

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有业务异常描述（如"余额不足"、"超出限制"） | 无业务异常 |
| 有系统异常描述（如"超时"、"服务不可用"） | 无系统异常 |
| 每个异常有对应的处理方式 | 异常无处理方式 |

---

## PD-6 — 状态转换

**MAC**：状态图完整，转换条件明确

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有状态图或状态列表 | 无状态描述 |
| 每个状态转换有触发条件 | 转换无条件 |
| 状态转换覆盖所有可能路径 | 有遗漏的转换路径 |
| 初始状态和终止状态明确 | 无初始/终止状态 |

**注意**：如果功能不涉及状态机（如纯展示页面），可标记为 N/A。

---

## PD-7 — 用户旅程与前后端交互场景

**MAC**：涉及用户交互的 PRD 必须有用户旅程；场景清单完整，含同步/异步标注

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 涉及用户交互的 PRD 有“用户旅程”章节 | 出现用户动作（点击、填写、提交、选择、上传、下载、搜索、筛选、确认、取消、登录、注册）、页面流程（页面、入口、列表、详情、弹窗、表单、向导、步骤、跳转、返回）、业务互动（支付、审批、邀请、分享、通知、提醒、反馈、授权、配置）、状态反馈（加载、成功、失败、空状态、错误提示、进度、撤销）或多角色协作信号，但无用户旅程 |
| 用户旅程覆盖角色与目标、入口与前置条件 | 只有功能清单，未说明用户从哪里进入、要完成什么目标 |
| 用户旅程覆盖主路径、分支路径、异常路径 | 缺少主路径或异常路径；缺少分支路径且未说明“不适用原因” |
| 用户旅程步骤映射到 FR / AC | 旅程步骤无法追溯到功能需求或验收标准 |
| 有前后端交互场景清单 | 无场景清单 |
| 每个场景标注同步/异步 | 未标注同步/异步 |
| 涉及 AI 的场景标注调用方式 | 涉及 AI 但未标注调用方式 |
| 场景覆盖所有用户故事的核心流程 | 有遗漏的核心流程 |

**Prompt 约束**：先判断 PRD 是否涉及用户交互。若涉及，必须检查用户旅程完整性；缺失用户旅程、缺少主路径、缺少异常路径时标记 BLOCK。缺少分支路径但明确说明“不适用原因”时，不按缺失分支路径 BLOCK；若该原因仍标记 `[需确认]`，可标记 WARN。若确认为纯后端/无人工交互 PRD，可标记 N/A，但必须引用文档中的“不适用原因”。
