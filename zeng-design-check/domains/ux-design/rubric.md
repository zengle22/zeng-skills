# UX 设计检查 Rubric (UX-1–UX-7)

D3 UX 设计域检查项。基于 ITERATION-DOCUMENT-CHECKLIST v2.1 §2.3。

---

## UX-1 — 设计原则

**MAC**：>= 3 条，每条有说明 + 示例

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 至少 3 条设计原则 | 少于 3 条 |
| 每条原则有说明（为什么选择这条原则） | 原则无说明 |
| 每条原则有示例（具体如何应用） | 原则无示例 |

---

## UX-2 — 核心页面交互流程

**MAC**：页面跳转 + 关键交互点完整

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有核心页面列表 | 无页面列表 |
| 有页面间跳转关系 | 无跳转关系 |
| 关键交互点有操作说明 | 关键交互点无说明 |
| 覆盖所有用户故事的核心路径 | 有遗漏的核心路径 |

---

## UX-3 — 状态表达规则

**MAC**：等级/计算/颜色/图标映射完整

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 涉及等级的有映射规则（如 VIP 等级 -> 颜色） | 有等级但无映射 |
| 涉及计算结果的有展示规则 | 有计算但无展示规则 |
| 颜色使用有语义定义（如红色=警告） | 颜色无语义定义 |
| 图标使用有含义说明 | 图标无含义说明 |

**注意**：如果功能不涉及等级/计算/颜色/图标，可标记为 N/A。

---

## UX-4 — 设计令牌引用

**MAC**：明确引用现有或新增令牌

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 引用现有设计系统令牌（如 Ant Design、Material UI） | 无令牌引用 |
| 新增令牌有命名和定义 | 新增令牌无定义 |
| 令牌使用一致（同一概念用同一令牌） | 令牌使用不一致 |

---

## UX-5 — 文案风格指南

**MAC**：口吻 + 禁忌词 + >= 3 个微文案示例

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有文案口吻定义（如"友好"、"专业"） | 无口吻定义 |
| 有禁忌词列表 | 无禁忌词列表 |
| 至少 3 个微文案示例（按钮文案、提示文案、错误文案） | 少于 3 个示例 |

---

## UX-6 — 平台差异策略

**MAC**：H5 vs 小程序功能/交互/权限差异

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 说明了 H5 和小程序的功能差异 | 未说明功能差异 |
| 说明了交互差异（如手势、导航） | 未说明交互差异 |
| 说明了权限差异（如定位、分享） | 未说明权限差异 |

**注意**：如果只支持单一平台，可标记为 N/A 并说明原因。

---

## UX-7 — 错误状态 UX

**MAC**：异常展示方式 + 文案风格

| PASS 条件 | FAIL 条件 |
|----------|----------|
| 有错误状态展示方式（如 toast、弹窗、页面） | 无错误展示方式 |
| 有错误文案风格定义 | 无错误文案定义 |
| 错误状态有恢复引导（如"重试"、"返回"） | 错误状态无恢复引导 |
| 覆盖网络异常、服务异常、业务异常三类 | 有遗漏的异常类型 |
